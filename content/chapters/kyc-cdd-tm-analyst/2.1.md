# Identity verification and document authentication

Before any CDD can happen, the firm must answer a prior question: is this person who they say they are? Identity verification is the foundation — and it is harder than it looks, especially at a distance.

## What must be verified

For an individual customer, the core identity elements are:

- **Legal name** — as it appears on government-issued ID.
- **Date of birth** — used for sanctions matching and age-related products.
- **Address** — typically verified against a utility bill, bank statement or registry record.
- **Government identifier** — passport, national ID, driving licence — the document itself.
- **Liveness** — proof that a real, present person is completing the verification, not a photo or a deepfake.

Each element needs verification against an independent source — the document is one source, the verification database or registry is another.

## Document authentication

A passport or ID card is not self-proving. Authentication checks:

- **Authenticity** — is the document genuine? Security features, holograms, chip data, printing quality.
- **Validity** — is it expired? Is it the current version of the document type?
- **Ownership** — does the person presenting it actually own it? This is where liveness and facial matching come in.
- **Consistency** — does the data on the document match what the customer declared?

In remote onboarding, document authentication is usually automated — OCR reads the document, chip data is verified where available, and facial comparison matches the selfie to the photo. Analysts should understand what the automation checks and what it does not.

## Common failure modes

- Accepting documents that are expired or about to expire.
- Verifying the document but not the person — a genuine passport presented by someone else.
- Skipping address verification because the customer "seems fine".
- Treating a document image as proof without checking authenticity features.
- Not recording HOW verification was performed — the method matters as much as the result.

## The verification record

Every KYC file should show: what documents were provided, how each was verified, what databases or registries were checked, when verification occurred, and who or what performed it. An examiner should be able to reconstruct the verification without asking you.

## Takeaways

- Verify name, DOB, address, government ID and liveness — each against independent sources.
- Document authentication = authenticity + validity + ownership + consistency.
- Remote onboarding relies on automation; understand what it checks and what it misses.
- Record the verification method, not just the result — method is evidence.
